claudi0 · 事件横幅重设计

横幅只为一瞥存在

横幅存在的唯一理由：用户没盯着终端时，把「声音事件」转译成一瞥可得的视觉事实，让人决定「要不要现在切过去」。 它不是通知中心，不是日志，不承载任何「以后再看」的信息——那些属于列表与详情。 由此推导内容与风格；下方三个变体是同一套内容规范的三种视觉表达。

现状问题（对照 EventNoticeProjection 与现行视图）

问题 1 信息优先级倒置

主行是「宿主 · 事件类别」——先回答「谁在叫」，再回答「要不要动」。但声音已经承载了宿主身份，视觉是冗余通道，应优先回答行动问题。

问题 2 系统语言，不是用户语言

「待响应」「信息性」是事件分类学，不是人的诉求。人需要的是「等你授权」「本轮已结束」——动词短语，可直接转化为动作。

问题 3 副行给了人读不懂的索引

8 位 hex 会话短 ID 对人几乎没有辨识度；项目名才是人脑里的索引。发生时间只在详情里，折叠态无法判断「这条还新鲜吗」。

问题 4 紧急度梯度为零

阻塞类（授权 / 输入 / 中断）与信息类（本轮结束 / 子任务结束）在折叠态视觉权重几乎相同；「查看来源」按钮对所有事件一个说法，语义模糊。

内容规范：从一瞥推导

P1 先答「要我停下来吗」

主行 = 行动句。阻塞类用「等你 × ×」的未完成态；信息类用「已 × ×」的完成态。完成态整体降一级视觉权重——它不需要你做任何事。

P2 宿主降为次要成分

宿主名保留但不再是主语重心，以次级色前置；多 agent 并行时它仍是必要信息，但决定「切不切」的是诉求，不是名字。

P3 项目名 + 相对时间进副行

副行 = 「项目 · 相对时间」。会话短 ID 从一切一瞥界面移除，只保留在详情（那里有复制按钮，ID 才有用武之地）。

P4 一态一主动作

阻塞类折叠态给一个事件色动词 chip（去授权 / 去输入 / 去查看）；信息类零按钮。详情页主按钮统一「打开来源」，复制与移除降为次级。

P5 事件色只上图形与小面积

色即语义的纪律不变：事件色用于脊柱 / LED / 字形 tile / chip 等图形与小面积元素，正文对比度由 text / text-2 保证，全部过 ContrastSuite 现行断言口径。

P6 时间用相对，时刻用等宽

一瞥界面（折叠 / 列表）用「刚刚 / 3 分钟前」表达新鲜度；绝对时刻（14:32）只出现在详情，用等宽数字。

主行=宿主+用户语言动词短语 ·副行=项目名+相对时间 ·会话短 ID→仅详情 折叠态不出现的字段不是丢了，是被正确地降级到了列表与详情——每一瞥界面只保留决定「切不切」所需的最少字段。

A行动优先

折叠态是一句完整的行动句：事件色脊柱标出紧急度，阻塞类右侧给一个动词 chip，信息类整体降一级且无按钮。 三个状态的信息密度梯度最平缓，适合「横幅经常出现、多数时候不重要」的使用现实。
