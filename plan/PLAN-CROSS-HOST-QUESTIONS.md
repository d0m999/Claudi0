领域决定见 [ADR 0018](../docs/adr/0018-separate-question-intent-and-observation-evidence.md)。
研究稿继续保留为研究材料，不替代本计划或实际验收记录。

## 已接受的行为

| 信号 | 声音 | 展示与证据 |
| --- | --- | --- |
| 精确提问工具 `PreToolUse` | notification | 瞬时「即将提问」；只说明调用意图，不改「需要你」 |
| 可靠明确输入请求 | notification | 沿用「需要你」；不表示整个任务暂停 |
| 普通 idle | 原有信息提示 | 不升级为明确待答 |

本阶段沿用五事件、默认组/工作区解析和现有提醒期限、容量、移除规则。

## 实施顺序和产物

1. **P0 Codex 入口验证**：记录当前实际客户端版本、同步/异步工具 hook、请求和会话
   身份；核查公开 App Server 是否能只读观察已有会话且不接管请求。受限 rollout
   原型只读取显式指定单文件的新增有界字节，在内存选择必要字段，不扫描历史会话，
   不保存问题、答案或原始行。不能证明明确请求时仅投影调用意图。开发 flag 和 GUI
   生命周期门禁保持独立；正式接入待证据决定。
2. **P1 Claude Code 与共享基础**：`AskUserQuestion` 精确 matcher、版本 binding、
   入口拒绝合同、身份去重、独立播放路径、多 binding 的 Event 聚合、逐类型当前回执
   及「即将提问」。目录证据未取得前用默认组。
3. **P2 WorkBuddy Desktop**：记录实际 Desktop 的提问工具、回调及身份。没有目标
   证据时交付缺口，不增添猜测 matcher。
4. **文档与证据**：保留 Vibe Island 来源与版本，区分 hook 与会话观察；交付入口
   对照、覆盖与失败场景、延迟和真实验收矩阵。

## 接口约束

- `HostQuestionTrigger` 单独持有版本、精确工具名、matcher、会话与请求字段名。
- 输入合同在副作用前执行；不允许敏感重复键、错误类型、截断、超限、超时和旧安装。
- 请求去重与既有 1.5 秒播放抑制分离；不同请求/会话/安装彼此独立。合法 callback
  仍记录其真实活动及播放回执；失败不记为播放成功，静默不补播。
- 连接事务沿用安装/配置锁与 CAS；清理精确自有命令，第三方和未知字段保留。
- 提示来源分为 hook 与开发会话观察，后者不具有 installation 或 hook activation。
- 跨源只能按已证明相同的请求身份关联；没有身份关联就不开两个主声音入口，也不按
  相近时间合并。当前 Codex 未配置提问 hook，因此观察原型没有平行提问声音入口。

## 验收矩阵

状态与执行结果见 [本轮实现验收](../docs/validation/cross-host-questions-2026-09-27.md)；
Codex/WorkBuddy/Vibe Island 入口证据见 [入口验证](../docs/validation/cross-host-question-entry-2026-09-27.md)。

| 层次 | 必须验证 |
| --- | --- |
| 输入 | 正常工具、相似名字、大小写、身份缺失、字段类型、重复键、超限、截断、超时；非法零副作用 |
| 配置 | 缺/宽/重复 matcher、混代、幂等、断开、并发修改；第三方和未知字段；五事件计数 |
| 并发与声音 | 同请求、不同请求/会话/代次、紧邻 Stop；静默、锁失败、播放器启动失败 |
| 展示 | 意图瞬时且旧 Attention 不变；明确请求进入提醒；idle 不升级 |
| 观察 | 同步/异步、快答/取消/自动答、历史、半行、截断/替换、格式、权限、退出、隐私恢复 |
| 真实宿主 | 精确工具回调、当前安装回执、真实问题界面、人工听音分别记录 |
| 原生 | 非抢焦点、键盘/VoiceOver、明暗、中英、既有阅读/移除 |

自动门禁：helper 和 GUI executable harness、`scripts/test-hook-cli-contract.sh`、
GUI Debug build、catalog JSON、`git diff --check`。涉及设置展示还执行贡献指南的
固定基线门禁。安装验收候选时另跑 Release/打包/体积检查；本地构建不能代替原生、
真实宿主、人工听音、双架构、签名、公证或正式接受。
