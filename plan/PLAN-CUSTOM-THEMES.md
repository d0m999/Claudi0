# claudi0 自定义 GIF 与完整主题方案

状态：基础产品范围已确认，独立交互原型已交付；层级关系与免费／Pro 交互仍在细化，正式功能尚未实施。确认与原型交付日期：2026-10-19。

本方案记录用户逐题确认的产品范围，供原型评审和后续开发使用。当前已交付独立浏览器原型，生产代码、配置迁移和收费系统尚未实施。本文涉及的新领域合同需要在实施设计中同步修订相关 ADR、`CONTEXT.md` 和 `DESIGN.md`，不以本文件代替现行实现说明。

## 用户价值与首版范围

主要面向已经持续使用 claudi0 的用户，让用户把自己的宠物、角色或表情素材融入日常提醒，提供个性化与情绪价值。用户愿意为此付费仍是待验证的商业假设。

首版优先做好 GIF 本地导入，并将声音、五事件动画和横幅外观组织为可保存、可切换的完整主题。“导入”指在本机选择文件并保存本地副本，不需要账户、云同步、分享或素材市场。

## 主题内容与作用范围

一个主题包含以下内容：

| 内容 | 已确认规则 |
| --- | --- |
| 声音 | 保存后独立于制作时使用的源声音包；源包后续修改或删除不改变已保存主题 |
| 事件 GIF | 五个公共事件各有一个独立槽位，允许只配置部分事件 |
| 横幅外观 | 少量经过设计的官方配色预设，包含当前原版外观 |
| 菜单栏图标 | 可选的个人静态图标；未配置时使用原版图标 |

新建主题默认填入原版五个提示音，作为固定初始内容。这个默认值不随当前默认组、工作区或进入页面的路径变化；需要沿用某个现有主题的声音与外观时，通过复制该主题开始。

声音包库保留独立的管理与创作入口。首版五事件动画作为主题内部的一组配置保存与编辑，不提供独立命名、保存、管理的动画包，也不新增动画包管理页。

五个事件沿用现有稳定身份和语义：

| 事件 | ID |
| --- | --- |
| 任务开始 | `task_start` |
| 本轮结束 | `stop` |
| 执行中断 | `stop_failure` |
| 待响应 | `notification` |
| 子任务结束 | `subagent_stop` |

默认组选择一个完整主题。工作区可以选择“跟随默认主题”或指定另一个完整主题，不逐项混用默认主题与工作区主题。

例如，默认组使用猫咪主题，工作区 A 指定机器人主题，工作区 B 跟随默认主题：A 的声音、GIF 和横幅外观共同使用机器人主题，B 使用猫咪主题。之后切换默认主题只影响跟随默认的工作区。不同工作区并发产生横幅时，各自保留对应主题。

同一事件的声音与横幅必须使用同一次主题选择结果。用户在界面中选中的编辑目标、最近收到的事件，以及声音播放成功与否，都不能让声音和横幅取到不同主题。

音量、五事件声音开关、静音规则、目录匹配和适用事件来源继续作为独立配置。切换主题不重新打开已关闭的事件，也不改变静音或提醒时机。音频缺失或播放失败不能因此压制原本应展示的横幅。

菜单栏属于全局界面，个人图标跟随默认主题，不随工作区事件来回变化；首版仅支持静态菜单栏图标。

## GIF 导入与编辑

- 首版仅接收 GIF，导入后保留原始素材的本地副本，供以后重新选择片段和裁切。
- 首版逐事件导入，不提供多文件批量分配界面。可编辑主题的每个事件行支持拖入单张 GIF 或选择文件，随后进入该事件的裁切预览；每次导入的目标事件明确固定。
- 保持横幅角色区域约 32 pt，不因自定义素材扩大横幅；编辑器提供实际大小预览。
- 可以只给一个事件设置 GIF。未配置的事件固定显示该事件的原版图标，不借用默认主题或其他主题的 GIF，并明确标为“使用原版图标”。
- 支持选择最长四秒的片段，默认从源文件开头开始，保持原速；短片段在横幅展示期间循环。
- 非正方形素材默认保持比例完整显示，允许留白。用户可以手动裁切、缩放主体，不拉伸；同一裁切区域应用于整个片段，并能播放预览检查主体移动。
- 首版自动处理大尺寸 GIF：用户选好片段和裁切后，生成适合横幅实际显示尺寸的播放版本，不要求用户先自行压缩。保留原始素材，预览展示处理后的实际效果；处理失败时保留该事件原有配置。此流程接受处理等待与额外本地存储占用，具体处理资源上限仍待实施验证。
- 每张 GIF 保存一个静态代表帧。默认提供代表帧，用户可在选定片段内重新选择，供静态偏好或 Reduce Motion 使用。
- 首版不加入变速、背景移除或复杂视频剪辑。

Claudio 仍在运行时，关闭设置窗口不取消已发起的 GIF 处理，任务继续在后台完成。结果只更新对应主题的草稿，再次打开时可查看；用户明确保存后才用于提醒。界面提供“取消处理”供用户主动停止。本规则仅确认关闭设置窗口的行为，退出应用及重启后的处理恢复另行细化。

横幅继续使用现有四秒阅读预算，不为了播完素材延长展示。声音每次提醒只触发一次，GIF 在可用阅读时间内循环，二者不要求精确同步。悬停暂停 GIF 和阅读计时，不暂停或重复已经触发的声音，也不为了匹配动画而截断声音。其他焦点、队列和暂停行为沿用现行横幅合同。

动画只装饰已有事件事实。权限请求、明确输入请求、普通通知与提问意图的动作或中立静态投影继续遵循现有语义；自定义素材不把“本轮结束”改称“任务完成”，也不改变导航和待接手判断。

## 外观与预览

首版采用官方配色预设，暂缓任意颜色、边框、纹理、背景图和装饰的自由编辑。具体配色及预设数量由后续原型确定。

配色预设保持共同的字体、布局、按钮和事件语义。预览展示真实横幅内容与用户自己的 GIF，支持切换五种事件及浅色、深色外观，让用户能判断实际大小下的效果。

预览与实际提醒隔离。编辑、导入、裁切和试配色只更新编辑器预览；手动试听沿用现有试听规则，不产生真实宿主事件或导航动作。

主题预览提供“播放提醒”，由用户主动点击后，一起试听当前编辑事件的声音与 GIF：声音触发一次，GIF 按横幅播放规则展示。切换事件、配色或调整裁切只更新视觉，不自动发声。

## 草稿保存与主题删除

未保存的修改自动保留为本地草稿。关闭设置窗口或重启 claudi0 后可以继续编辑；草稿不影响正在使用的主题，只有明确选择“放弃修改”才清除草稿。免费预览用户同样保留其创作草稿。

新主题首次保存后不自动启用，不改变默认组或任何工作区当前使用的主题。“保存”与“应用到…”分开；保存后显示尚未使用，由用户明确选择应用目标。

对于已经被组使用的主题，点击“保存”后，整套修改才对后续新事件生效。主题可以在只配置部分事件时保存。一个主题被多个组引用时，保存后的修改统一影响所有引用组，编辑界面说明影响范围。

若只想改变一个工作区，先复制为独立主题，再分配给该工作区。修改共享主题与复制独立主题的后果必须清楚可见。

复制主题只取源主题最近一次已保存的内容，不包含未保存修改。源主题的草稿继续保留；复制操作不保存、清除或改写源草稿。副本与源主题独立编辑。

删除被引用的主题前，列出受影响的默认组或工作区，并要求选择替代主题。确认后统一切换引用并删除，保留各组音量、事件开关和静音规则。内置原版主题始终保留，作为可用的替代选择。

## 免费能力与未来 Pro 边界

未来按主题实际使用的能力判断是否需要 Pro，不以“用户创建了主题”作为收费条件。

| 能力 | 已确认的商业化边界 |
| --- | --- |
| 现有声音包管理、声音定制、工作区声音配置和内置动画 | 继续免费 |
| 仅包含原有免费能力的主题 | 免费创建、复制、保存和应用 |
| 自定义 GIF 的导入、裁切、配置、完整预览和草稿保留 | 免费体验，在入口说明实际应用所需权益 |
| 在真实提醒中启用自定义 GIF、个人菜单栏图标等新增付费能力 | 日后需要 Pro |
| 自定义 GIF 权益 | 一次解锁完整能力，五事件全部开放，不按文件、事件槽位或替换次数收费 |
| 额外配色预设的收费归属 | 暂不确定，随整体商业化设计决定 |

不能在用户完成创作后才首次告知付费要求。保存方案不代表本次接入收费或立即限制新能力；实际收费时间、价格、买断或订阅、授权校验和权益变化后的处理规则另行设计。

### 层级与免费／Pro 交互复核（结构已确认，交互待细化）

用户要求先梳理工作区、主题、声音与动画的层级，并同时考虑免费与付费功能区。2026-10-20 确认保留独立声音包库，动画组放在主题内部编辑，首版不增加动画包管理页。下列具体权益提示与免费快速换包等交互仍待细化，不表示原型已经更新。

| 层级 | 职责与建议呈现 | 权益边界 |
| --- | --- | --- |
| 默认组／工作区 | 选择整套主题，管理音量、事件开关与适用范围 | 既有配置能力保持免费；启用的主题是否需要 Pro 取决于其中实际使用的能力 |
| 主题 | 组织五事件声音与动画、横幅配色及可选个人图标 | 主题容器和仅含免费能力的主题不整体标为 Pro |
| 主题内容 | 五事件仍按行并排呈现声音与动画，外观在下方 | 原有声音与内置动画免费；自定义 GIF、个人图标的实际使用属于未来 Pro；额外配色待定 |
| 声音包库 | 保留现有独立声音包管理与创作入口，为主题提供素材 | 既有免费能力保持免费；与主题声音的所有权衔接仍需细化 |

建议侧栏继续按“工作区、主题、声音”的任务分工组织。主题编辑中只在具体付费能力入口标注 Pro，并说明可免费制作预览、实际启用需 Pro；含付费内容的主题在选择器中显示“含 Pro 内容”，不将整个主题页设为付费入口。

首版采用独立声音包库与主题内动画配置的结构。声音包继续独立管理；五事件动画随主题保存与编辑，不增加独立动画包库。源声音包与主题内声音的具体衔接，不由这个结构决定代替。

本次复核发现两个必须补齐的流程，尚未定稿：

- 现行主面板在选定工作区后，更换声音包立即生效；声音包的共享修改也影响所有使用者。新方案要求主题声音独立于源包，尚未定义如何承接既有免费快速换包与共享编辑流程，不能宣称这些流程已经设计完成。
- 给已经被使用的主题保存修改，本身就会更新真实提醒。因此未来权益检查必须覆盖这条生效路径，不能仅检查首次“应用”。免费用户在该主题内试配 Pro 内容时，草稿仍须保留、正在使用的版本保持有效；如何继续保存免费部分且不丢失 Pro 草稿，需要单独确认，不能静默裁掉付费内容或默认启用。

## 与现行领域合同的关系

以下差异必须在实施设计中显式处理：

| 现行依据 | 本方案带来的变化 |
| --- | --- |
| [CONTEXT.md](../CONTEXT.md)、[ADR 0005](../docs/adr/0005-use-global-sound-defaults-with-sparse-surface-overrides.md) 中，默认组与工作区选择完整声音配置，工作区不逐字段继承 | 引入完整主题选择及“跟随默认主题”；这种跟随仅针对整套主题，不扩展为音量和事件开关的逐字段继承 |
| [ADR 0021](../docs/adr/0021-own-all-event-sounds-in-packs.md) 中，声音包是事件声音映射的唯一所有者，共享修改影响所有使用者 | 已保存主题需要独立于源声音包，同时仍须保持单一映射所有者；复制、所有权与既有免费编辑流程的衔接需要专门设计 |
| [事件动画规格](PLAN-EVENT-ANIMATION.md) 与 [DESIGN.md](../DESIGN.md) 中，角色选择是全局偏好，工作区单独动画不在原功能范围 | 新主题把声音、动画与横幅预设按同一工作区选择结果组合，需要调整全局动画偏好和事件投影的衔接 |
| `DESIGN.md` 中，菜单栏使用固定品牌图标 | 允许默认主题提供可选个人静态图标，原版图标仍作为缺省选择；不扩展为 App 或 Dock 图标定制 |

“独立于源声音包”不要求复制系统提示音文件。系统提示音仍按本机名称引用，并沿用 ADR 0021 的可用性处理；主题独立性针对源声音包后续的编辑或删除。

实施时继续复用 app-lifetime `SoundPackLibrary` 与既有写入边界，统一设置保持一个 retained window 和类型化路由。不得为了主题编辑再增加声音包扫描缓存、第二份声音映射或平行设置窗口。

旧声音配置与用户素材需要显式迁移设计，保证已有配置、声音包和免费流程可继续使用。配置 schema、数据路径、主题资产所有权、版本捕获与跨进程传递方式尚未定稿，本文不指定具体实现。

## hook 与动画资源的性能复核（2026-10-20，设计建议）

用户提出按工作区使用不同主题是否会加重 hook。当前主题运行时尚未实施，以下结论来自源码与既有性能材料的只读核对，不是新增主题功能的性能实测，也不代表下列实现建议已经获得确认。

现行 hook 已按可信目录与事件来源选择一个工作区声音配置，读取所选声音包的 manifest，不扫描整个声音包库。声音播放器启动后不等待播放结束；横幅通过非阻塞本地 datagram 发送，不等待 GUI 回复。配置、目录匹配、版本与授权检查、活动和回执等同步成本仍存在，不能因为声音与通知不等待完成就将 hook 称为零成本。依据 `WorkspaceSoundRules.swift`、`Play.swift`、`HostHookRunner.swift` 与 `EventNoticeTransport.swift`。

工作区使用不同主题不要求增加 hook 触发次数或为每个工作区新增常驻进程。建议在已有工作区解析后，只读取当前事件所需的已保存主题信息，让声音与横幅使用同一主题身份及版本；具体消息协议仍待设计。GIF 原图、裁切、缩放与播放素材准备留在导入／编辑阶段，事件消息不携带媒体内容，hook 不等待 GUI 解码或为主题功能发起网络请求。

GUI 当前共享动画资源，但缓存依靠固定的四张内置图集获得上界，尚无面向任意用户主题的淘汰策略。虽然最多三条横幅同时可见，`EventAnimationView` 的资源加载 task 并不受 `isVisible` 限制；隐藏布局测量与静态画廊也可能触发加载。未来主题数增长时，不能直接沿用永久保留所有资源的方式，也不能仅凭可见横幅数量估算内存。

建议为用户动画规定处理、解码与缓存资源上限，同一素材版本共用缓存；区分静态缩略图／布局测量与实际播放需求，避免隐藏视图解码完整动画。资源加载失败或尚未完成时，使用原版事件图标，正常声音与横幅流程继续。把工作移到 GUI 仍会消耗整机 CPU 和内存，需要一并验证。

实施前后的性能验收需分别覆盖工作区规则数量、冷／热素材、多主题并发与设置预览，比较 hook 同步返回耗时及 GUI 加载、播放的内存与响应。具体规模和预算仍待确认；沿用 [ADR 0031](../docs/adr/0031-measure-hooks-before-changing-execution-policy.md) 的证据分层，不借本功能改变宿主执行策略或启用暂停中的缓存实验。现有 hook 历史基准只包含单条工作区规则，不能证明多主题增量；下文 GIF 导入探针也不能作为每次 hook 的成本。

## 原型验证场景与后续验收

原型围绕真实 GIF 的“导入 → 编辑 → 预览 → 应用到工作区”流程，至少覆盖以下场景：

1. 从一个事件开始，完成片段选择、等比显示或裁切、静态帧选择和实际大小预览；其余事件明确使用原版图标。
2. 在五种事件和浅深外观之间切换，检查主体可辨认、正文可读、交互可达。
3. 关闭后继续编辑本地草稿；保存前实际提醒不变，明确放弃后草稿清除。新主题首次保存不切换任何组的主题，明确选择应用目标后才启用。
4. 默认组、跟随默认的工作区和指定主题的工作区同时存在，切换及并发事件的声音与横幅保持一致。
5. 修改共享主题、复制后单独修改，以及删除被引用主题时，都能看清受影响范围。
6. 循环、悬停暂停、四秒阅读预算和静态模式符合约定，声音不因 GIF 循环重复触发。

这些场景是验证要求，本轮浏览器验证结果见文末，不代表原生 UI、真实声音或宿主回调已验收。正式实现还需按 `CONTRIBUTING.md` 运行适用工程门禁，并分别记录原生布局、键盘与 VoiceOver、真实音频、真实宿主及发布证据。

### 后续细节确认

Q29：用户否决“新建主题根据入口自动复制默认组或工作区当前主题”的建议。新建与复制保持明确分工；希望沿用某个现有主题的内容时，由用户明确选择复制该主题。新建主题的提示音初始内容随后由 Q31 确认。

Q32：用户确认首版自动处理大尺寸 GIF。选好片段与裁切后生成适合横幅的播放版本，保留原始素材供重新编辑；预览反映实际处理结果，处理失败不覆盖原有配置。这项自动处理流程尚未接入当前原型。

Q35：用户确认采用逐事件导入。每个事件提供拖入单张 GIF 与选择文件的入口，导入后进入该事件的裁切预览；首版暂不提供批量分配界面。

### GIF 处理耗时探针（2026-10-19）

在本机 Apple M1、16 GiB 上，用独立的 ImageIO / CoreGraphics 探针处理三份现有 GIF，每份运行三次。选取开头不超过四秒的帧，先强制解码到源尺寸 RGBA，再等比缩放到 64 × 64 像素，编码为逐帧 PNG 并写入临时目录与帧时长 JSON。64 × 64 是本次测量规格，不据此确定正式播放素材格式与分辨率。

| 素材 | 源尺寸 | 文件大小 | 处理帧数 | 总耗时中位数 | 三次范围 |
| --- | --- | --- | --- | --- | --- |
| `G-compare-idle.gif` | 396 × 192 | 37,168 B | 16 | 26.6 ms | 22.1–136.4 ms |
| `ghost-preview.gif` | 1008 × 612 | 1,389,880 B | 36 | 263.8 ms | 258.0–552.4 ms |
| `event-meaning-preview.gif` | 1248 × 981 | 3,346,112 B | 40 | 607.4 ms | 601.9–637.0 ms |

计时包含读取、帧信息解析、实际像素解码、缩放、PNG 编码和文件写入，排除编译、进程启动及目标目录创建。源文件此前已读取，属于暖缓存；写入没有执行 `fsync`。首次 ImageIO 调用开销保留在结果中。输出尺寸与逐帧时长已核对，源素材内容和权限未变。

这组样本的九次处理均少于 0.64 秒，不支持将明显长等待视为常态。它不是正式 App 导入性能承诺，未覆盖任意大 GIF、后段片段定位、正式资产持久化、原生 UI 响应或动画视觉正确性。此探针不代表自动处理功能已经实施。
