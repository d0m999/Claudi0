# 将全部有效生成音频保留到本地生成记录

2026-10-07，用户决定自动保留所有成功生成且通过校验的音频，包括未采用的结果，并在“声音”页提供“生成记录”管理入口。生成有等待和潜在费用成本，未选中的音频仍有复用价值，因此生成记录独立于当前候选会话和声音包长期存在。代价是新增持久音频的管理、存储占用与清理责任。

## 决策边界

- 保存不以先采用到声音包为条件；关闭表单、切换目标或重新生成，不移除已成功保存的生成记录。
- Claudio 仍运行时，关闭生成表单、离开声音页或关闭设置窗口，均不打断本次已显式发起的生成；它继续在后台完成，并将有效结果与原始描述保存到记录。关闭或离页结束原表单的采用上下文，不自动采用结果，也不恢复旧采用凭证；再次使用从当前事件按历史记录选用。
- 后台继续使用点击时的输入、profile、路线政策及同一总截止时间，不因关闭或重开重新计时或重复请求；重新打开设置读取同一任务的实际状态与已保存结果。主动点击“取消生成”直接停止本地等待，不二次确认，保留原描述供编辑；取消沿用迟到结果隔离规则，不删除已有生成记录，不承诺远端停止生成或计费。已生成但保存失败的有效音频须按待处理结果规则处置，不能通过取消绕过放弃确认。本决定不授权应用退出后继续执行。
- 生成期间切换 AI 服务仅改变下一次生成的选择，不取消当前任务或改变其快照；当前进度与结果仍归属原 profile，既不伪装成新服务结果，也不自动采用到新的上下文。切换服务不绕过单个在途生成限制，也不自动发起生成。
- 有未完成生成时，用户常规退出 Claudio 前先提示退出会停止接收结果，并提供“暂不退出”和“退出”。前者保留原任务继续，后者结束本地等待并退出。已有有效音频但保存失败时，退出前同样提醒“部分音频尚未保存，退出后可能丢失”，提供“暂不退出”和“仍然退出”；留下可继续重试保存，仍然退出不承诺未保存结果跨重启恢复。没有未完成生成且没有尚未保存的有效结果时不为此额外提示。已保存记录不受退出影响，退出不承诺远端取消或停止计费。
- 整个应用同时只允许一组生成，跨包、事件与服务共用此限制；不提供并行或排队。当前任务结束或取消后，若仍有保存失败的有效音频，须先保存成功或明确放弃，才能恢复新生成资格；关闭界面、切换目标或服务不解除该限制。下一组仍须用户显式发起，不隐式替换、自动启动或重放生成请求。
- 后台生成完成并保存后，只在应用内的生成记录入口显示完成状态，由用户点击查看和试听；不发送 macOS 系统通知，不自动打开生成表单、播放或采用结果。保存失败不得显示为已保存完成。
- 后台任务的进度与取消操作也通过声音页的生成记录入口访问，不另加设置窗口工具栏快捷入口；记录页区分当前生成与已保存的生成组，在途任务不能显示为已保存音频。
- 记录只接收符合既有路线成功政策的有效音频；允许部分成功时，保存实际有效结果，不保存无效或未验证音频。
- 保存不自动绑定事件，也不修改任何组的选包。当前候选的采用资格仍受当前会话约束，历史音频再次使用不能沿用失效的候选身份或采用凭证。
- 不能把临时目录残留直接作为记录库。记录的本地保存结果须有明确事实，不能以生成成功推断持久保存成功。
- 2026-10-08，用户确认保存到生成记录成功是选用的前提。已下载且通过校验的有效结果保存失败时，保留当前音频供手动试听，显示实际原因和“重试保存”，保存成功前不允许选用。重试只保存现有音频及记录信息，不重新请求 AI 或重新下载；保存成功也不自动采用或恢复旧采用凭证。此项不承诺未保存结果跨应用重启恢复。
- 保存失败后允许先关闭生成表单。应用持续运行期间，关闭表单、离开声音页或关闭设置窗口均不丢弃这些有效结果；生成记录页顶部以“待处理”区域展示未保存状态和原因，提供手动试听与重试保存，与已保存组分开。重开读取同一批结果，不重复生成；保存成功后转为已保存记录，管理页仍不提供选用入口，旧采用凭证不恢复。退出提示遵守上述规则，不承诺跨重启恢复。
- 明确放弃待处理结果时，先显示仍未保存音频的实际数量并确认移到废纸篓；取消保留结果，确认后只处理这批未保存音频，不影响已保存记录或声音包副本。移到废纸篓失败不降级为永久删除，不假报成功；剩余未处理结果继续阻止下一次生成。音频仅通过访达废纸篓找回，不提供应用内撤销，也不承诺恢复原记录或旧采用资格。无效下载的既有清理规则不变。
- 同时在本机保留与该次结果对应的原始声音描述，供日后回看和复用；之后修改输入不覆盖旧记录的描述。
- 2026-10-08，用户进一步确认保存该次生成时间、实际所用服务（含 profile 地区）及每条音频经校验的实际时长。来源归属原任务，不随后续服务选择改变；不以请求目标时长代替实际时长。
- 每条记录音频同时保留可由用户修改的显示名称，确认改名后持久保存。重命名不改写原始描述、生成信息或分组，不修改声音包中已有副本的名称、文件或事件绑定，也不重新生成。
- 生成记录按每次生成分组；每组的描述与对应有效音频一起呈现，并可展开、收起。
- 已保存记录一直保留，由用户手动删除；不设置自动到期时间，也不因未采用或空间占用自动清理记录。
- 手动删除支持单条音频和整组；仍有其他音频时保留该组及原始描述。删除最后一条音频时一并移除该组记录与描述，不留下空组；删除整组不影响其他生成组。
- 删除采用移到 macOS 废纸篓的方式，允许找回文件；不直接永久删除，也不由应用清空废纸篓。移到废纸篓失败时不得退化为永久删除或假报成功。不提供应用内撤销或恢复入口，用户通过访达废纸篓找回音频文件；找回文件不承诺自动重建生成记录、显示名称或原分组信息。
- 单条移到废纸篓不二次确认；整组操作需先显示将删除的音频数量并确认，取消不删除。确认按触发的操作区分，单条为组内最后一条时仍不额外确认。
- 采用到声音包的音频为独立副本。即使已被采用，仍允许删除生成记录；删除仅作用于记录及其持有的音频，不移除包内副本或事件绑定。
- 历史音频从声音包详情的事件“设置…”入口选用，先确定包和事件，再选择记录；独立的生成记录管理页负责试听和管理，不提供选择目标的“用于…”操作。
- 上述音频、可编辑名称、原始描述、生成时间、实际服务与时长之外的信息未获隐式保存授权。内部声音方案、凭据、远端音频 URL 等不因保存记录而获准持久化，既有敏感信息边界继续适用。

## 与既有合同的关系

本决定部分修订 ADR 0016、`CONTEXT.md` 及 `PLAN-CONSUMER-TTS-EXECUTION.md` 中未采用候选随会话清理、正式音频仅通过采用进入包，以及原始声音描述只在会话内保留的持久化边界。候选会话可以失效，已经归档的音频与描述不因此消失；生成记录与包内声音分别表达，不能将历史记录变成另一种声音包。

关闭生成表单、离开声音页及关闭设置窗口还部分修订 `PLAN-SETTINGS-EXPERIENCE.md` 和 `PLAN-CONSUMER-TTS-EXECUTION.md` 的关闭即终止约定：界面可结束而已发起的生成继续，旧采用上下文仍失效。ADR 0011 的路线总截止时间、音频校验及显式采用要求继续适用。

两份计划中切换 profile 即取消当前 generation 的条款也由本决定修订：新选择只影响下一次生成，原任务的有效结果按原 profile 保存；不得用旧结果覆盖新上下文。

2026-10-08，用户在整体可点击原型后选择 A，确认声音设置交互定稿；记录管理与历史音频再次使用的呈现见 [声音设置重设计 D1–D55](../../plan/PLAN-SOUNDS-INTERACTION-REDESIGN.md)。本 ADR 与该设计记录共同限定保存字段和交互；未列出的字段不获隐式持久化授权。`accepted` 表示决策已确认，HTML 只演示内存状态。2026-10-08 原生记录存储、生成协调器及页面已接线；升级从空记录库开始，不迁移旧临时音频。验证结果和未完成的原生／外部门禁见[实施证据](../../plan/PLAN-SOUNDS-IMPLEMENTATION-EVIDENCE.md)，文件格式及恢复边界见[持久化说明](../sound-assets-storage.md)。
