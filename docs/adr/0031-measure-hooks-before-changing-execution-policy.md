# 先测量 hook，再按宿主验证执行策略与版本观察缓存

[Issue #218](https://github.com/d0m999/Claudi0/issues/218) 确定分阶段边界：先建立可复跑基线，
用户确认分场景预算后才实现执行策略和版本观察缓存，随后处理回执热路径。本 ADR 接受该顺序
及行为边界；**不表示后续机制已实现，也不批准任何 timeout 或耗时预算**。
测量与预算保存在性能报告，不进入领域词汇表。

2026-10-10 局部授权：用户接受基线报告的 Core 分场景预算及版本超时拒绝路径 ≤2 秒测试上限，
仅放行版本缓存的本地实现与隔离验证。这调整了完整预算包通过后统一开工的次序，不代表第一阶段
全部验收。宿主策略、生产启用、回执优化继续暂停，现有回执历史和活动计数不动。
缓存目录必须显式注入；默认生产工厂不提供目录，因此新源码的默认路径也不启用持久缓存。
连接、修复和诊断仍走强制探测；只有显式注入的 hook resolver 可选择验证后复用。

2026-10-10 E1 局部实验授权：用户仅放行本地 resolver 实现和隔离验证，实验性地分离真实探测与
显式缓存刷新。两种 `resolve` 模式均不签名、填充或续期；合格持久观察只能由独立 `refresh`
入口创建。被动发现、状态和默认诊断保持强制真实探测且不写缓存。本段只调整本地候选的验证范围，
不批准 GUI/adapter 接线或自动维护触发；下文历史“版本诊断强制探测刷新”不适用于默认 `doctor`。
完整替代提案仍见 [ADR 0033](0033-refresh-host-version-cache-outside-hooks.md)，其状态保持 proposed。
E1 完成后另行建议是否继续 E2；不自动进入 E2，不确认生产冷预算，也不启用生产缓存。

沿用 `handleHostHook` 和已有环境注入，通过一个默认关闭的类型化测量上下文记录单调时钟跨度
和有限结果。上下文只存内存，驱动器输出；不增加 hook 输出、普通日志或持久遥测。跨度可嵌套，
不可相加推导总耗时。Core 隔离、Debug CLI、确切 Release helper、真实宿主及人耳听音分别列证据。
发起数、接收、启动、活动、当前回执、归档、提示分别核对，提前拒绝不得作为成功路径样本。

预算确认后的共享执行策略与事件语义绑定分离，由 adapter 拥有宿主 schema。Claude Code 保持
同步并使用确认后的有效 timeout；普通 async 不执行配置 timeout，因此首版不启用。Codex 对
当前已支持事件逐一验证 async 的超时、短会话、取消、并发、乱序、去抖及送达，失败或缺证据则
该事件统一有界同步，不按猜测的运行模式切换。WorkBuddy 保持同步，先验证当前 timeout 合同；
Kimi/OpenCode 不改变策略。不新增脱离宿主管理的进程或 helper 总期限看门狗。更新纳入既有
自有 hook 完整性检查与接入维护，备份、第三方顺序、未知字段、显式关闭及 Codex 信任边界不变。

预算确认后的 `HostVersionResolver` 是版本观察缓存唯一 owner，提供验证后复用及强制探测。
只存规范化宿主版本，完整 scope 仍结合 Claudio 版本与 binding 生成。首版只接纳 Claude Code
原生版本目录和 Codex standalone layout 1；真实 `--version` 是版本值来源，布局/包元数据及
系统签名 API 决定冷填充资格，禁止每事件启动 `codesign`。每次命中重新定位调用路径、实际目标
和依赖元数据身份，执行保留原调用路径及 `argv[0]`。探测前后身份一致才发布缓存，探测不在
事件发布许可内进行；私有、有界、原子发布，非阻塞写锁，每宿主四项，有效期上限 10 分钟，
异常时钟 miss，无负缓存。未知布局、npm、wrapper、shim、缺失、损坏、过期或变化均同步真实
探测；失败拒绝，不用旧值。缓存写失败不废弃本次成功结果。hook 可复用，连接/修复/版本诊断
强制探测刷新。版本缓存命中不构成当前激活，installation、启用意愿和 GUI 身份仍实时复验。

ADR 0005 的 Git common directory 身份和 ADR 0025 的发布许可不变。Git 本轮只测量及回归，
不做目录前缀预筛、身份缓存或算法修改。回执后续优化仍保留同步当前回执和归档的两次持久发布、
原锁、每来源 20 条、按 mtime 的 30 天清理。只允许普通非 symlink 文件数量 <=20 时跳过 JSON
解码/排序；超过 20 时保留内容时间的完整精度排序、损坏项与旧文件名处理。不延迟、不新增队列、
不复用未经身份验证的已写对象、不删除 fsync。

没有选择统一 async，因为宿主 timeout、teardown 与信任合同不同；没有选择只看任意 inode/mtime
或 TTL 的版本缓存，因为无法证明 wrapper 的依赖身份。没有选择文件名剪枝或延迟归档，因为会
改变精度、旧格式和失败合同。AUHAL、拆二进制、daemon 与首帧出声量化保留为独立实验，不以
外部设备数据或进程启动成功代替 Claudio 出声证据。
