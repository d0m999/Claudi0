# 分开瞬时提示和带版本的待接手提醒

阅读时间、来源应用打开和行动优先展示由 [ADR 0019](0019-open-verified-source-applications.md)
补充；打开 App 不触发精确返回移除，原有版本、冻结与保留期限不变。

本决定部分替代 ADR 0012 的全事件近期历史与消除规则：普通进展只用于当前瞬时展示，
授权、明确输入请求、执行中断及未知关注信号保留为「需要你」。继续由 `EventNoticeModel`
唯一拥有内存状态，保留非激活窗口、独立声音链、隐私清空与 TTL；没有第二个任务数据库。

完整主会话按 epoch、Surface、installation、projectKey、sessionID 归并；每次新 UUID
更新版本——但同会话一旦建立有效观察水位，缺失或不可排序（不晚于既有水位、epoch 之前
或未来）的观察不再更新版本，防止旧 schema 或乱序来源覆盖新内容。阅读列表冻结顺序和内容，
动作捕获版本并重验。Stop、查看和复制不移除提醒；
移除原因区分手动、精确返回确认、可信后续提交、过期、容量与隐私清空，不表达任务完成。
生产精确返回与按后续提交自动移除均默认关闭，adapter 真实验证后才可启用。

保留上限为 50 个最新版本、50 个冻结版本及 1 个瞬时版本，每版本最长 30 分钟；
去重和顺序元数据各最多 256 条且同样限时。TTL 优先于阅读与在途动作。静默不补播，
锁屏与睡眠按原因集合处理，部分恢复不能重启接收。用户主动复制不被隐私清空覆盖剪贴板。

## 多横幅与待展示队列修订（现行 · 2026-10-06）

用户确认采用主原型的多横幅方案。本节替代上方“普通进展只用于当前瞬时展示”、
“1 个瞬时版本”及单瞬时展示限制；其余版本、冻结阅读、独立 TTL、声音与隐私合同保留。
这项修订表示实施授权，不表示原生人工或真实宿主验收完成。

唯一 `EventNoticeModel` 拥有最多 50 条展示与待展示提示，按 FIFO 保留到达顺序，
最多三条同屏，先到在上。普通进展只在这份有界临时集合中存在，不进入待接手提醒。
展示 ID 与捕获动作版本分别判断：同一提醒的合法新版原位替换展示或排队项，旧动作失效；
已展示新版获得完整阅读预算且不重播入场，其他条目的位置与预算不变。
收起后的提醒收到合法新版时，以新的展示 ID 追加。展示满额拒绝新增条目，
不抢占已有 FIFO；合法待接手提醒独立保留。栈内合并展示容量提示，展示溢出与提醒容量淘汰分别计数。
提醒容量淘汰不能挤出已经接受的展示条目，展示捕获版本仍遵守自身 TTL。

每条预算由同一模型、注入时钟与调度器独立计算；下一次展示提交合并新增入场批次，
入场完成后才起读。悬停、键盘聚焦整个栈、展开待展示列表及模态交互暂停全部预算。
按完整卡片实测高度选择可见 FIFO 前缀；小屏退回队列保存剩余时间，重新展示不重置。
单条关闭只收起自身；Escape 清空展示栈与待展示队列，待接手提醒和冻结阅读集合保留。
退场帧立即失去交互及无障碍资格，保留原层级样式；TTL 与来源关闭、隐私清空也清除退场帧。

`SessionNavigationCoordinator` 保留全局单在途与原始三秒预算，按完整捕获动作保存独立反馈。
开始 B 不清除 A 的结果，关闭 B 不能取消 A；收起正在导航的横幅取消所属请求。
只有精确返回收起并移除捕获版本；应用回退、`requestSent`、失败和重试保留横幅、提醒及剩余预算。
版本失效、TTL、能力代次与隐私清空释放对应结果，迟到回调不得回填。

窗口仍只有一个 retained 非激活 `NSPanel`，作为透明容器；卡片承担动效，窗口不重复淡入。
纱层仅作用于背景和装饰，正文、按钮与阅读轨保留正常对比度。
来源 OFF 清除该来源展示与队列，按 ADR 0025 保留提醒、冻结阅读及主动导航能力。
通知关闭、锁屏、睡眠、退出即时清空来源、待展示与退场帧、计时和结果；静默恢复不补播。
量化呈现规格与验证边界见 [DESIGN.md](../../DESIGN.md) 的多横幅修订。
