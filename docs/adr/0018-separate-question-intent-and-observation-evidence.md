# 区分提问意图、明确输入请求与会话观察证据

采用 2026-09-27 用户确认的跨宿主提问计划。五个公共 `Event` 保持不变；提问复用
`notification` 的声音包映射、音量和开关。精确提问工具的 `PreToolUse` 只生成瞬时
「即将提问」，不新增或更新同会话的「需要你」。可靠明确输入请求沿用 ADR 0013 的
提醒期限、容量、版本和移除规则；普通 idle 仍为信息提示。异步提问不表示任务停止。

每个提问类型由版本化 binding 统一拥有工具白名单、matcher 与身份字段合同。覆盖数
按公共 Event 去重；当前回执按 binding 展示，旧通知或授权回执不能激活新增提问。
触发范围改变进入 installation scope。Connect、Repair、Disconnect 保留第三方 hook、
未知字段和既有 binding ID；新增类型不借宿主级 ready 冒充已观察。

入口在任何活动、回执、声音或提示之前严格校验有界输入、事件名、精确工具名、字段
类型及请求/会话身份；重复敏感字段和失效安装代次拒绝。提问以宿主、安装、会话、
请求身份去重，先消费再尝试声音与提示。消费记录仅含摘要与时间，限 256 条、30 分钟；
容量/锁/存储失败关闭，不驱逐仍有效身份以重播。不同请求不使用旧宿主播放锁或 1.5 秒
时间戳；静默或播放失败不会安排补播。合法重复回调的活动和回执仍记录实际结果。

本决定扩展 ADR 0012 的提示来源边界：开发期 Codex 会话观察可经进程内入口投影至
唯一 `EventNoticeModel`，使用独立 provenance 和运行代次，不伪造 hook binding 或
installation，不经过 datagram、回执、激活或活动写入。GUI 生命周期内只有一个显式
开启的观察者；禁用、退出、锁屏和睡眠使运行代次失效，恢复从新文件末尾开始。
来源只能证明 function call 时只能生成提问意图，不能用缺少结果推断明确输入请求。

本决定同时明确 ADR 0005 的目录边界：新增提问事件与会话观察来源必须各自取得目标
回调目录证据，才能匹配工作区；目前均使用默认组。Codex 原型不自动成为生产接入，
公开 App Server 的存量读取也不视作不干扰原客户端的订阅证明。WorkBuddy 提问需真实
Desktop 工具名、回调及身份字段证据，CLI/SDK 文档不能替代。

实施与验收见 [开发计划](../../plan/PLAN-CROSS-HOST-QUESTIONS.md)；未验证项以对应
验收矩阵为准，不由该 ADR 的 accepted 状态推断实现或验收通过。
