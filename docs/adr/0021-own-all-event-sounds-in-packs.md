# 声音包统一拥有事件声音来源

用户在「声音」编辑包内映射，在「默认组／工作区」选择包、音量和事件开关。每个事件只有一个
`PackEventSoundSource`：包内文件或本机系统提示音名称。这个决定取代 ADR 0020 的组级覆盖，
使切包、试听、覆盖度、诊断和自动播放始终指向同一份映射。代价是编辑共享包会同时影响所有使用者，
因此界面在编辑旁列出有效使用者；内置包仍先复制再编辑。

文件映射继续是字符串。系统音映射为 `{"system_sound":"Basso"}`，首次写入时将 schema 升至 2，
已有更高整数版本保留。只存名称，运行时从本机系统目录解析；不可用时明确提示并停止该事件，
其他可用系统音继续播放。系统音不进入包内文件清单、复制音频或分发资源。

同包内一个系统音名称或规范化文件引用只能新绑定给一个事件。菜单显示已占用事件；文件选择、
导入后绑定、AI 采纳和系统音选择在同一 `packs.lock`／CAS 边界再次校验，失败保留原绑定。
既有重复继续播放并显示提示，允许逐项修正，不将整个包判为损坏。异步操作的绑定期望比较完整
来源，不能把系统音误当作未映射或同名文件。未知 manifest 元数据继续原样保留。

复用 app-lifetime `SoundPackLibrary` 和已有包编辑 owner。共享包库发布来源、覆盖度、可用系统音及
重复提示；系统音可用性在观察刷新时重读。原有 helper 更新校验移至包级系统音写入。
新建提示音组可以用第一条系统音发布：先在隐藏暂存包中绑定并验证，再以独占重命名发布。
取消或失败不发布空包；发布后查看该包，其余事件未配置，不自动改变任何组的选包。

旧顶层 `system_sounds` 和工作区 `systemSounds` 保留原始 JSON，但退出有效配置校验和播放解析，
包括损坏或未知形状的值。旧写入口拒绝操作。检测到旧字段时提供前往「声音」重新配置的提示，
不推测用户想修改哪个共享包，也不自动生成包或迁移覆盖。

本决定不改变 ADR 0005 的目录匹配、独立组音量和事件开关，不改变 Provider／候选安全边界。
自动化回归、原生双语／最小窗口／键盘／VoiceOver、真实听音、真实宿主回调和发布证据分别记录。
