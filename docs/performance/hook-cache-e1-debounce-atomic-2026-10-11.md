## 隔离范围和计时合同

在上一轮诊断副本基础上创建一个独立临时副本，保留其有限阶段 observer。只新增：

- `writeLastPlayedTimestamp` 的原子写入总跨度。
- `writePrivateAtomic` 中 `write`、`fsync`、`rename`、defer 中 `close` 的独立计时。
- 一个 TaskLocal 范围标记，确保这四类计时只属于去抖时间戳，活动/回执等文件写入不混入。

没有替换 syscall、注入延迟、放宽签名、改 Git 或改变失败处理。每次 syscall 恰好执行一次；
返回后立即保存返回值和 `errno`，记录耗时后恢复 `errno`。close 仍处于原 defer 中，
原 write 循环、fsync→rename→close 顺序、私有权限及原子发布保持原样。
运行前的编译 seam 校验了失败返回值/errno、成功返回值/errno、一次执行及范围退出后不记录。

全部新增计时只在临时诊断源码中，未加入产品 API。发布标记、结果及有限时间跨度只收集于内存，
由独立 benchmark 输出；没有文件名、路径、时间戳内容或原始事件内容日志。
计时及记录本身有开销；原子写入总跨度含记录开销，四个 syscall 的子跨度不含随后写入 observer 的开销。

## 结果与逐事件边界

以下均为诊断观察值，不是新的性能预算或验收结果。分位数取 nearest rank，n=500。

| 区间 | p50 ms | p95 ms | max ms |
|---|---:|---:|---:|
| 去抖原子写入总跨度 | 0.514875 | 0.738750 | **2.448000** |
| write | 0.032083 | 0.083375 | 0.347625 |
| fsync | 0.074500 | 0.117000 | 0.280833 |
| rename | 0.116834 | 0.143458 | 0.308125 |
| close | 0.003709 | 0.005834 | 0.051208 |
| 播放锁 inclusive 跨度 | 1.309167 | 2.339708 | **4.769375** |
| 完整 hook | 26.512333 | 33.577250 | 59.332375 |

播放锁和原子写入均没有 ≥20 ms 的样本，不能直接确认历史 28.110792 ms 的来源。
各 syscall 的 max 来自不同调用，不能相加为一次最慢原子写入。

最慢原子写入是 pair 78，总计 2.448000 ms。同一次调用的四个 syscall 为：
write 0.042000、fsync 0.071958、rename 0.137500、close 0.005791 ms。
它们是同一次原子调用内顺序执行且不互相嵌套的四段，总计 0.257249 ms；
其余 2.190751 ms 包含目录检查、临时文件创建、权限、字符串/数据处理、observer 记录及可能的调度，
没有更细计时，不能单独归因到目录或内存开销。

本批完整 hook 仍有较慢调用，但去抖原子写入没有相应的 20–30 ms 长尾。
完整 hook 的 p95 33.577250 ms 高于原 Core 31.10 ms 参考线；该组是不同诊断二进制、observer 开启，
不能作为原关闭组门禁的重复验收，更不能以它声称修复或通过。原 E1 超限继续保留。

## 结论

本轮证据不支持把历史 28.11 ms 当作已确认的 fsync 阻塞，也不能排除某个 syscall
在那一次未分段的历史调用中偶发变慢。尚无依据修改该原语、删除 fsync、延迟写入或改变去抖语义。
只完成了细分计时与有限复现尝试，**没有确认历史长尾的唯一原因**。

本轮到此停止。Git 算法和性能/体积门禁不变；生产冷预算不冻结；E2、生产启用、宿主策略及第三阶段
继续暂停。现有回执历史和活动计数没有通过本轮生产写入入口修改；无 commit、push、发布或正式验收。
