# 将版本缓存冷填充移出 hook 的设计评审

2026-10-10。结论：**值得继续一次限定范围的本地隔离实验，尚不足以接入生产或自动刷新。**
候选应消除 hook 未命中时的签名与填充，保留真实版本探测；收益取决于实际刷新触发能否覆盖事件。
迁移成本、10 分钟后的退回行为及原 Core 门禁失败必须同时呈现，不能只展示预填充后的命中耗时。

2026-10-11 状态补记：E1 本地实现与隔离实验已结束，用户决定停止追加长尾诊断，暂不进入 E2。
固定候选有正确性和体积通过记录，但性能未全部通过，历史长尾来源和实际周期收益仍未确认。
最终判定见 [E1 收束报告](hook-cache-e1-closeout-2026-10-11.md)；下文是实验前的设计评审，
其中继续 E1/E2 的建议不再构成下一步授权。生产缓存默认关闭，完整 ADR 仍为 proposed。

## 本轮范围与证据

本轮只读评审实现与历史测量，新增本文和 [ADR 0033 提案](../adr/0033-refresh-host-version-cache-outside-hooks.md)。
没有实现新策略、构建候选、运行基准、调用真实 hook、安装或启动 app，也没有执行连接、修复或 `doctor`。
Git 算法、共同仓库身份、性能和体积门禁不变；生产冷预算未冻结，生产启用、宿主执行策略及第三阶段继续暂停。
现有宿主配置、回执历史和活动计数没有被本轮读写。无 commit、push、发布或正式验收。

评审基于 `main` 的 `d61c49d5ddc7c1ca12a54aa8d14ad8b80494ab95` 及当前未提交改动，不是 clean HEAD。
24 份相关源码、合同及报告的摘要和工作区状态保存在
`dist/hook-cache-refresh-design-2026-10-10/review-source.json`、`before-status.txt`。
本轮的静态结论与历史运行证据分开：

| 证据 | 可以支持的结论 | 不能支持的结论 |
| --- | --- | --- |
| 当前 `HostVersionResolver` 与调用链 | 两种模式共用未命中后的签名/发布分支；生产默认不注入缓存目录 | 新设计已经实现或性能通过 |
| [上一轮完整配对及 Git 分段诊断](hook-git-tail-and-cache-decision-2026-10-10.md) | 9,600 条配对结果中 9/16 分组超预算；Git 等待及其他长尾仍存在 | 改变缓存填充位置会修好 Git 长尾 |
| [历史真实签名完整 Core 测量](hook-arm64-cache-validation-2026-10-10.md) | 每格 n=30 时，Claude/Codex 热命中 p50 约节省 10.73/11.79 ms；签名冷填充成本明显 | 确切生产 helper 的收益或刷新周期内实际命中率 |
| [历史签名组件诊断](hook-signature-diagnosis-and-helper-size-2026-10-10.md) | 严格内容校验存在读取等待，较早 Codex 极值 3.10 s 不能删去 | 新刷新路径的上限或本机 OS 的唯一根因 |

没有新增性能数据，也不重写历史失败。已批准的 Core 预算和版本超时拒绝路径 max ≤2 s 继续有效；
这不是整个连接、签名刷新或真实宿主事件的 2 s 上限。

## 评审发现与处理

| 发现 | 源码依据 | 设计约束 |
| --- | --- | --- |
| 不能只搬动一个默认 callback | `HostVersionResolver.resolveVersion`，`HostActivationScope.discoveredVersion/current` | 强制探测与缓存刷新分别调用，避免任意 `forceProbe` 自动签名或续期 |
| 被动状态路径很多 | `HostDiscovery.detect`、两个 adapter 的 `inspect`、连接结束后的 `inspect`、`DoctorIntegrationsEnvironment` | 普通发现、状态、快照及默认 `doctor` 不承担冷填充 |
| 现有维护不保证刷新 | `HostIntegrationManager.maintainOnce` 在已配置且非 force 时提前返回；GUI 有 60 s discovery fallback | 不能宣称启动、每分钟检查或重新聚焦必定填充缓存 |
| 默认诊断明确只读 | `Subcommands.Doctor.configuration` 声明“不写入、不播放” | 缓存刷新必须是显式选择的版本诊断动作，默认 `doctor` 的合同不变 |
| 连接目前在 operation lock 内解析 scope | `ConcreteHostIntegrationAdapters.connectLocked` | 签名刷新在连接事务及既有锁释放后运行，不把关闭或其他来源卡在签名检查后面 |
| 原 force 模式混合了探测与填充 | `HostVersionResolverSuite` 的 force-refresh、跨进程 cold-fill 测试 | 将填充断言迁到显式刷新入口，并保留失败、并发与身份失效检查，不能只删除旧断言 |

上述约束是进入实验前的必需设计修正。单纯给现有生产 `scopeFingerprint` 闭包注入带目录的 resolver
会使多处状态读取产生签名或磁盘发布，不能采用这种接线方式。

## 缓存资格与唯一所有者

`HostVersionResolver` 继续唯一拥有定位、版本探测、资格检查、失效和持久缓存。
GUI/manager 只决定何时请求刷新，adapter 继续拥有宿主 schema；不能另建 GUI 版本数据库或缓存年龄 owner。
缓存仍只保存规范化真实版本及资格身份、观察时间，完整 fingerprint 仍由 `HostActivationScope` 生成。
刷新成功、配置写入和当前激活是不同事实；本轮不需要修改已有 `CONTEXT.md` 词汇表。

首版资格保持原实现范围及检查强度：

- Claude Code：已识别的原生 versions 目录，版本目录名为受支持的 release 形状；真实输出须与布局版本一致。
- Codex：standalone layout 1，核对 `codex-package.json` 的布局、版本、variant、入口及资源/path 目录。
  Claudio 的 arm64-only 分发不等于缩减宿主签名检查架构；沿用现有 host layout 资格规则。
- 冷填充使用现有 Apple anchor、厂商 identifier/team requirement，保留
  `kSecCSCheckAllArchitectures | kSecCSStrictValidate` 及完整内容检查，不启用跳过内容的 flags。
- 每次命中重新定位原调用路径，核对实际目标、链接链、普通文件身份、纳秒 mtime/ctime、所有权/模式及相关包元数据。
  执行保留原调用路径和 `argv[0]`；不执行解析后的 target 来绕开 shim。
- 私有目录 0700、普通单链接文件 0600、有界读取、原子发布、非阻塞锁、每宿主最多四项、有效期上限 600 s 不放宽。
  异常时钟、到期、身份变化、损坏、缺失均未命中；不保存失败版本或负缓存。
- npm、wrapper、shim、未知布局不获缓存资格，继续真实有界探测。缓存不授予事件接收资格；
  installation、启用意愿和当前 GUI 内核进程身份仍按原发布边界实时复验。

厂商签名只决定版本观察能否复用，不是事件授权或供应链绝对证明。
Apple 的本机 SDK 头文件明确要求代码在校验时及结果使用期间不被修改；本设计沿用前后身份检查，
不宣称 stat 身份能证明任意同用户恶意修改。Apple
[公开实现](https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_codesigning/lib/SecStaticCode.cpp)
通过 `staticValidate` 完成校验；它不是本机 macOS 27 私有实现的逐行证明。
本轮没有重新调用 Security validator 验证当前厂商安装。

## 解析与刷新接口候选

保留现有两种解析模式，另在同一个 owner 上增加显式刷新入口。以下是拟议职责，**不是已存在的新 API**：

| 调用 | 职责 | 签名/冷发布 |
| --- | --- | --- |
| `resolve(host, mode: .reuseValidated)` | 验证命中；未命中按原调用路径探测一次，成功返回本次版本，失败拒绝本次事件 | 不签名、不创建缓存、不填充、不续期 |
| `resolve(host, mode: .forceProbe)` | 忽略缓存，取得真实版本；被动发现/状态/默认诊断使用不带目录的环境 | 不签名、不填充、不续期 |
| `refresh(host, reason:)` | 显式强制探测并执行严格资格校验，合格才发布 | 唯一可增加/更新合格条目的入口 |

生产工厂仍默认 `cacheDirectory: nil`，连接/修复也不自动获得目录。未启用缓存时不运行签名或缓存锁操作；
真实版本仍由原强制探测取得。显式刷新可以因锁忙或安全发布前提不足而早退，结果必须区分“未执行刷新”与
“执行了版本探测但失败”；版本诊断所需的真实版本可独立探测，不能回退到旧缓存充当诊断结果。

hook 未命中不是新的业务拒绝条件。已识别候选在探测期间身份变化仍按原合同拒绝；成功探测不因
签名不合格、锁忙或缓存不可写被废弃。版本探测失败不返回旧缓存值，不启动播放器、不发布回执、活动或提示。
正常/近零/延迟输出的版本探测、1 s 探测 timeout 及包含清理时间的 ≤2 s 测试上限保持不变。

“hook 不填充”不应偷换成“任何失效都不能写”：保留必要的旧观察撤销行为，其锁忙处理与失败边界要有回归。
hook 撤销只能删除对应资格，不能刷新时间、生成目录或补写合格条目。默认只读诊断不接入这一写路径。

显式刷新返回类型化结果，至少分别表达真实版本结果和缓存状态：已发布、不具资格、身份变化、
写锁忙、写失败、已取消/过期请求。不能仅返回 `String?` 后向调用方谎报“缓存已刷新”；
连接状态与本次可缓存性分别呈现，未取得缓存资格不新增接入阻断。错误结果和枚举只在明确诊断或隔离报告使用，
不增加 hook stdout/stderr、普通日志或持久遥测。

### 刷新顺序与并发

1. 连接/修复先按原强制探测、配置事务、installation 和授权合同完成，释放既有来源 operation lock、
   配置/installation 锁及事件发布许可。后续缓存刷新是可失败的独立步骤，不回滚已成功的连接、不清空旧回执。
2. 由现有生命周期 owner 持有刷新任务，按宿主在 utility 执行器上运行。可在既有动作的尾部 await，
   不占用 `MainActor` 或 manager actor 执行同步 Security 检查；其他来源、OFF 和 GUI 退出仍能前进。
   不增加 timer、daemon、脱离宿主管理的进程或无人管理的 `Task`。
3. resolver 使用私有的每宿主非阻塞刷新 operation lock 合并跨进程刷新；竞争者返回 busy，不能排队等签名。
   这个锁与缓存原子写锁分开，后者只围住撤销/发布。探测及签名均不在缓存写锁或事件发布许可内执行。
4. 若将覆盖同身份的旧观察，先在短写锁中原子撤销该条目，再探测。撤销不可完成则跳过本次缓存刷新，
   不启动这一刷新操作的签名检查；连接已有成功版本仍有效。需要真实版本时可另走无缓存强制探测。
   报告“刷新未执行”，不能声称完成了失败探测后的全局失效。移除旧合格条目不属于保存负缓存。
5. 刷新重新定位并捕获候选，调用原路径的 `--version`，记录成功观察时刻，再做严格签名检查。
   探测后、签名后及最终发布前均复验调用路径、目标、依赖身份与时间。以版本观察时刻计算 TTL，
   签名或等待发布不重新赠送 600 s；到期不得发布。签名或布局不合格只取消持久复用资格。
6. 最终短写锁内再次验证候选，原子发布并读回核验结果。当前同宿主刷新 operation lock 在全程持有，
   不让旧刷新后完成覆盖更新的观察；不能提前解锁后留一个仍可能发布的签名调用。
7. GUI 所属动作在 await 后复验生命周期/动作代次和关闭意愿；取消、退出、被新修复取代的请求丢弃结果，
   不发布缓存或更新连接快照。显式 CLI 版本刷新不要求 GUI 正在运行，但仍不启用来源或修改任何 installation。

第 3–7 项是待实现的并发合同，不是对现有实现的通过声明。实验先使用全新临时缓存根，避免新旧 writer 混用。
当前生产缓存从未启用，不需要迁移用户缓存或清理用户状态；将来若允许同根混合旧 writer，必须另行设计版本隔离。
不凭空增加持久队列、失败 tombstone 或另一套缓存 owner。

Security 调用本身仍可能很慢。当前使用的公开 `SecStaticCodeCheckValidity` 签名没有 timeout 参数；
本轮核对 SDK 公开头文件，不以开源树中出现的取消实现推定当前 Swift `Task.cancel()` 能中断该调用。
取消只承诺阻止迟到发布，不承诺立即停止底层签名耗时，也不把先返回 UI、后台仍运行的成本隐去。
若 utility 执行和代次复验仍无法保住关闭/其他来源的行为，停止接线实验，不加看门狗或放宽检查。

## 刷新时机与到期后的实际行为

第一版实验采取保守触发，不用缓存欠费、hook 未命中、无回执或 GUI 重新聚焦触发修复：

| 路径/事实 | 是否刷新 | 原因 |
| --- | --- | --- |
| 显式连接成功、显式修复成功 | 请求一次真实探测与严格刷新；纯幂等连接也须显式到达刷新步骤 | 不依赖 `maintainOnce` 的提前返回 |
| 自动维护实际完成连接/修复 | 同样在事务和原锁结束后请求一次 | 复用既有动作，服从 OFF，不新造接入动作 |
| 启动时已有完整连接；60 s 发现检查、wake、activation、普通文件提示 | 不单独启动签名刷新 | 当前实现不是刷新调度器；避免每分钟或每次焦点变化读取大二进制 |
| hook 缺失/过期/损坏/身份失效 | 只进行原有有界真实探测 | 避免把成本和重试重新搬回事件路径 |
| 默认 `doctor`、`integrations status`、GUI 诊断快照 | 不刷新；仍取得所需真实版本 | 维持只读语义，不能给所有诊断闭包注入可填充 resolver |
| 用户明确选择版本缓存刷新诊断 | 强制探测和严格刷新，明确报告资格与发布结果 | 作为独立 opt-in 动作；CLI/UI 入口名称与公开接线另行评审 |
| OFF、断开、GUI 退出或旧生命周期结果 | 不由维护刷新；hook 继续拒收 | 缓存不能制造新的接收资格 |

默认 `doctor` 与“显式版本缓存刷新诊断”必须区分，这是对 ADR 0031 中“版本诊断强制探测刷新”的必要澄清。
本轮不增加诊断按钮或 CLI flag。普通发现探测不得因此读旧版本；不把状态检查的 probe 偷换为缓存命中。

**到期不会自行填充。** 第一次成功刷新后的 600 s 内，身份稳定的事件可以复用；超过期限后，连续 hook
均恢复真实探测，直到下一次上述合格刷新。已有完整连接的 GUI 重启，也可能一直是 miss。
相同版本但二进制身份变化时，当前完整 scope 可能仍相同；不能依赖必然重接入来触发刷新。
新版本导致 scope 改变时，沿用原维护修复，不能由缓存刷新自己改 marker。

这缩小了首版收益范围，是明确代价。下一步先测触发覆盖，不能擅自用 60 s timer、滑动 TTL、命中续期或
延长 TTL 弥补。若只在刚接入的十分钟获益，应据实建议停止，或另行评审缓存专属维护触发；后者不在本次提案内。

## ADR 调整提案

[ADR 0033](../adr/0033-refresh-host-version-cache-outside-hooks.md) 为 `proposed`，只拟调整 ADR 0031 的
填充位置、解析/刷新职责和默认诊断边界；不改已接受的阶段顺序、预算授权或暂停项。
接受后在 ADR 0031 增加日期及引用，指出新提案替代“hook miss 冷填充”及含糊的通用诊断刷新解释。
保留旧 ADR 与历史报告，不直接把原合同改成仿佛从未存在。

ADR 0005、0025、0032 不变；`CONTEXT.md` 已声明版本缓存命中不构成当前激活，不添加缓存结构、TTL 或预算。
实验成功也不自动把 ADR 标成 accepted；生产授权、真实宿主、预算和发布仍分别决定。

## 隔离验证方案与停点

以下均为后续实验方案，本轮未运行。分两步，先证明 resolver 职责，再证明触发能产生实际收益。
不因移出签名而重置基线，保留原 bypass、原同步 cold-fill 候选及新候选的独立身份和配对来源。

### E1：本地 resolver 和完整 hook 隔离验证

- 从固定源码与脏文件摘要生成独立副本，只改 resolver、有关环境注入、缓存 suite 和 benchmark。
  不给生产工厂提供目录，不接真实 GUI/adapter、宿主策略或现有数据；实验根包含 config、GUI run identity、
  installation、locks、声音、回执及活动。播放器与提示使用模拟端点。
- 首先将原 suite 中隐式 cold-fill/force-refresh 断言迁到显式 `refresh`，保留跨进程读回及无缓存默认。
  新增：空缓存、多次 miss、到期及坏缓存均零签名/零冷发布；显式刷新后 hit 零探测/零签名；
  `forceProbe` 始终真实探测且不续期；默认诊断在已存在和缺失缓存根均不产生缓存写入。
- 所有既有资格与身份回归继续覆盖：布局/metadata/目标/链接/PATH 变化、原 `argv[0]`、同 inode 修改、
  过期/异常时钟、厂商签名不合格、输出不一致、探测中升级、未知 shim、权限/损坏/超限及写失败。
  正常、近零、延迟对照保持相同输出；超时和子进程清理结果分开，拒绝路径 max ≤2 s 不变。
- 刷新并发专项：同宿主跨进程竞争不等待；两宿主独立；撤销旧 entry 后 probe/signature 失败下一次只能 miss；
  刷新 operation lock 忙和短写锁忙分别核对；撤销失败必须没有启动刷新探测/签名；旧请求、退出或 OFF 发生在
  签名前后/发布前均不允许迟到发布；崩溃不能留下可用的未验证条目；成功版本不因发布失败被丢掉。
  不把“缓存写入失败”当成刷新成功，也不把 cache miss 当成事件拒绝。
- 完整 `handleHostHook` 覆盖原全部场景：完整/静音/去抖/不可播放、授权拒绝、旧 installation、锁忙、
  历史未满/20 条稳态、无工作区/普通目录/Git/损坏 Git。复验接收、播放启动、当前回执、归档、提示、活动和拒绝原因。
  Git 外部 worktree、submodule、symlink、损坏 `.git` 的共同仓库身份及失败关闭合同原样验证，不改解析算法。
- 真实签名组只读取已安装厂商二进制/元数据，调用真实 `--version` 和现有严格 validator；缓存仍写临时目录。
  新模式至少分开报告未预填充 miss、显式 refresh、命中、到期 miss、身份变化 miss、不合格布局和失败。
  refresh 包含撤销、探测、签名、发布及清理；hook 的 miss/hit 总跨度分别计时，不能把预填充从成本总账中删去。
- 每场景默认预热 10、测量 100、三轮；固定种子交替 A/B，observer 关闭作为门禁，observer 开销单列。
  每个样本断言目标分支；原始脱敏样本、源码/二进制摘要、构建、宿主身份、OS 与系统缓存条件完整记录。
  相同 Release full LTO `-Osize`、arm64-only，生产 helper 的正式 Release 仍不能注入测试根。
- 未插桩样本沿用原 Core 分场景门限，以最差单轮 p95 评价，不通过合并轮次或扣空进程耗时隐藏失败。
  真实签名 refresh 暂只提出独立预算依据，不套用组件或 Core stub 的绝对值，不冻结生产冷预算。
  任一身份/授权/计数回归立即停止；性能未过如实报告，保留失败与不完整批次，不重跑到绿。

因果对照不需要一个同时具备旧写策略和新写策略的生产 resolver。将旧、新候选分别构建为固定源码的独立
benchmark，并使用各自全新的临时状态；旧候选的 cold-fill 对照结果不冒充新策略结果，也不共用缓存根。

E1 结束交付独立前后对照和实际失败项，再决定是否进行 E2；不自动扩大到 GUI 接线或生产启用。
原 helper harness、相关 CLI/driver 契约、适用 GUI build/localization/diff 和原 arm64 体积门禁按实际变更运行。
不新增 Intel 要求、不拆二进制、不提高字节上限；本轮不把以前通过的 2,747,056 B 候选当新方案体积证据。

### E2：维护触发与收益覆盖的隔离评估

在 fake adapter、模拟 GUI 运行身份及临时状态中接线，保留默认 `doctor` 和状态检查只读。
模拟首次连接、已有完整连接的启动、显式幂等连接/修复、相同版本目标替换、新版本升级、60 s 检查、
重复 activation、OFF、退出和两宿主并行；验证只在表中许可的路径刷新，短事务锁不覆盖签名，迟到结果不发布。
用会阻塞的签名 fixture 验证 `MainActor`、manager 与其他来源可继续响应；不要用源码串检查替代执行。

先用可注入时钟模拟 0、599、600、601 s 及多周期事件序列，证明到期之后的每次回调真实 probe、不会隐式再填充。
合成序列不能证明真实用户事件密度；保留该项未验证，不读取现有活动摘要反推密度，也不保存原始事件。

每序列分别统计发起数、命中/未命中原因、刷新次数、版本/签名调用数与业务结果。比较三个总账：

1. 宿主事件阻塞：事件路径耗时合计及分布；
2. 维护成本：刷新完整耗时、CPU/I/O（若采集）、锁忙/取消及连接返回耗时；
3. 合计工作：所有事件探测加维护探测、签名和发布，不以热样本平均替代周期成本。

搬动签名只降低事件承担的冷成本，不自动减少系统总工作。历史 n=30 中位数算术示例需要 Claude 56 次、
Codex 14 次事件才抵消一次冷填充；新方案并没有凭搬动位置取消这个工作成本，亦不能沿用该次数作新验收阈值。
如果长会话在 600 s 后大部分事件仍 probe，或刷新拖住其他来源，就应停止继续接线，保持 cache-off。
缺乏真实事件覆盖数据时最多认定机制改善，不能判定生产收益。

上述临时根 Core 实验不需要新 macOS 账户、VM 或 Intel 设备。确切生产 Release helper 批量验收仍须有状态隔离，
目前未授权也未补齐；不能用本实验替代。真实宿主回调、人耳听音、签名/公证、macOS 12 实机及正式验收继续分别记录。
