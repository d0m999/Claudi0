## 假设与逐事件核对

先列四项可证伪假设，再分析阶段记录：持久写入/锁内处理、版本探测、Git 工作区查询、
首轮/执行顺序及 observer 对分布的影响。阶段跨度为 inclusive，播放器启动嵌套在播放锁跨度中；
下文不相加不同事件的 maxima，也不将相邻 observer 样本当成同一次调用。

### Core full-empty：首轮整体较慢，探测与写入均有长尾

E1 第 0 轮 observer 关闭的 bypass p50 为 15.311 ms，hit 为 9.194 ms；第 1/2 轮对应
bypass 10.658 / 10.287 ms、hit 6.087 / 5.706 ms。相同候选的两个模式首轮均较慢，
不是只发生在绕过缓存的分支，也不是只有一个极端样本。

observer 开启组的版本阶段第 0 轮 p50/p95 为 6.847 / 10.785 ms，第 1 轮为
4.974 / 6.189 ms；其他阶段也一起变慢。具体慢调用包括：

- pair 23：总计 84.755 ms，版本解析 55.018 ms。相邻关闭组为 36.408 ms，仍是另一次事件。
- pair 13：总计 68.540 ms，当前回执 23.552 ms、历史归档 18.369 ms。
- pair 60：总计 79.942 ms，播放锁覆盖区间 24.287 ms、归档 21.758 ms、工作区/声音 12.299 ms。

46 个关闭组超线调用与 45 个开启组超线调用中，31 个 pair 同时较慢，提示局部持续的运行环境波动；
不能将未记录阶段的关闭组精确归因。现有记录没有足够系统 I/O/调度证据来确定波动来源，
也不能把首轮较慢直接称为 OS 缓存冷启动或其他会话干扰。

### Core git-damaged：Git 是主要固定成本，最长尾不只来自 Git

第 0 轮 observer 开启的工作区/声音 p50/p95 为 13.835 / 16.257 ms，第 1 轮为
12.613 / 14.380 ms。Git 共同仓库身份算法及失败关闭行为没有变化。

具体慢调用有两种：pair 65 的总计 36.487 ms 中，工作区 18.930 ms、版本 6.381 ms；
pair 53 的总计 38.703 ms 中，工作区 15.046 ms、播放锁覆盖区间 10.693 ms。
关闭组 6 个超线调用只有 1 个相邻开启调用也超线，因此不能把 31.192833 ms 的门禁样本直接
解释为某一次 Git 查询耗时。工作区阶段只能证明热点范围，不能代替对子进程的逐次计时。

### Claude 替换刷新后 hit：历史记录没有阶段，不能追溯唯一原因

## 一次有限诊断探针

只建立了一个临时诊断源码副本，未修改共享工作区源码。沿用同一 E1 候选及 Release / full LTO /
`-Osize` / arm64 参数；新增有限计时涵盖授权复验、发布许可、installation 复验、完整回执写入、
进程祖先/导航证据、内层 autoreleasepool 回收，以及部分 `fsync`/`rename` 调用。
它不是生产 helper，也不是原 benchmark 二进制。新增计时会扰动耗时，不能用于验收。

每个目标只运行一个预设批次：预热 10、样本 100、observer 开启。三个直接 hook 场景和一个
Claude 替换刷新场景；每次刷新后运行两个独立业务根的 hook（未满及稳态）。
没有重跑原 12 场景/8 模式/3 轮矩阵，也没有根据耗时结果追加重试。

本机 macOS 27.0.1 / arm64；Claude 2.1.282、Codex 0.162.1 的二进制、调用路径和元数据
身份与原 native 批次完全一致。测量窗口为新加坡时间 01:43:51–01:44:15，0.5 s 间隔的
PID/PPID/进程名监测未发现编译/GUI harness 重叠；其他系统负载仍未完全控制。

500 个 hook 的接收/活动/当前回执/归档/提示各 500；播放启动 400（损坏 Git 的 100 次按预期
不启动）；版本探测 200，hook 签名 0。100 次替换刷新各真实探测/签名一次并严格发布。
各批次 exit 0、stderr 为空。播放器和提示发送模拟；不代表真实宿主送达或已出声。

捕获到的 git-damaged pair 46 总计 **51.431208 ms**：工作区 12.452083 ms，
版本 5.293458 ms，播放锁覆盖区间 **28.110792 ms**。
锁获取只有 0.030458 ms，锁内再次取得许可的锁获取 0.027125 ms；相关授权复验最大
0.141792 ms、installation 复验最大 0.074625 ms、发布许可获取 0.097208 ms。
该调用没有播放器启动；所以不能解释为锁争用排队、版本签名或播放器冷启动。

冻结源码中的该分支仍会读取并持久写入去抖时间戳。`writeLastPlayedTimestamp` 调用
`writePrivateAtomic`，包含私有目录检查、临时文件、write、fsync、rename 和关闭。
**本探针没有计时这一个原子写原语内部的 fsync**：已计时的活动/回执 fsync 不能代替它。
因此热点已缩到播放锁内尚未细分的去抖状态处理等区间，时间戳持久写入是优先核对对象，
但不能把 28.11 ms 直接报告成 fsync 的实测值。此次其余目标未复现原慢调用，未测到的原因保留未验证。

## 结论与边界

现有证据不足以支持针对 E1 缓存逻辑的性能修复，也不足以把 Git 子进程或回执裁剪视为唯一根因。
E1 未命中零签名及严格刷新后安全命中仍成立；剩余长尾包含既有探测和持久处理成本，
并受跨轮运行环境变化影响，但系统层原因尚未证实。

如果后续继续诊断，最小探针应只细分 `play.state` 的原子写入与 syscall，以及工作区的真实 Git
查询；在确认原因前不修改它们。原超限保留，生产冷预算不冻结，E2/生产启用/宿主策略/第三阶段暂停。
本轮无 commit、push、发布或正式验收；没有访问生产写入入口，不改现有回执历史和活动计数。

完整诊断证据位于忽略目录 `dist/hook-cache-e1-tail-diagnosis-2026-10-11/`：
`replay.py` / `replay.json`、`analyze.py` / `per-event-analysis.json`、诊断源码差异及构建日志、
四个单批次原始记录、`diagnostic-summary.json`、环境/身份/摘要与 SHA256 清单。
分析脚本校验分支计数；诊断构建成功，文档 `git diff --check` 通过。
未重新运行整套 helper/GUI harness 或生产 Release 门禁；临时附加计时不进入产品源码或发布产物。
