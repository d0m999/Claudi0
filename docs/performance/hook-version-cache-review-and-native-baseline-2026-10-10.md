## 复审：Spec

- 发现一个时钟缺陷：缓存时间 `(wall=10000, uptime=1000)`，本次命中开始 `(10100,1100)`，
  结束 `(10099,1100.001)` 时，两次相对缓存的新鲜度检查都通过，即使命中期间 wall 已回退。
  原实现没有检查开始到结束的连续性，违反“异常时钟 miss”。修复后捕获结束时间，同时要求
  `validInterval(started, finished)` 和缓存新鲜度成立，否则真实探测。原有双时钟偏移容差未改变。
- 两宿主回归在修复前为 130 checks / 2 failures，精确失败于“命中期间回退仍未探测”；修复后
  包含实际 hook 缓存解析的 targeted suite 为 140 checks / 0 failures，成功探测仍可使用。
- 同时发现并关闭上述构建前源码归属缺口。隔离目录、签名、逐样本结果及默认关闭策略符合规格。

Spec 共两项发现，均已处理；最严重的是命中期间时钟回退可复用观察。

## 冷路径预算的适用边界

最终数值仅作为**本机完整 Core 隔离测试提案**，尚未冻结。采用关闭 observer 的分组，保留三轮合并分布、
最差单轮 p95 和 max；冷填充、到期、强制探测各自报告。同机后续对照必须同时核对原同步分支和处理结果，
不能通过丢事件、缩短授权或跳过签名让数字更好。

原批准的命中分场景预算及版本超时拒绝 max ≤2,000 ms 继续有效。本轮受控 `.launchFailed` 不能替代原真实
子进程超时与回收证据；到期刷新使用注入双时钟，不能称已运行真实十分钟过期。
新增冷预算不覆盖 Git 规则、其他工作区/拒绝分支、生产 CLI、真实宿主等待或出声；这些仍各有证据缺口。

`--version` 的 1 s 期限只约束探测等待，真实签名 API 没有本轮新增的执行期限。
因此冷成功路径的测试预算不是运行时墙钟硬上限，也不据此写宿主 timeout 或新增 watchdog。
生产试用前需要独立账户/VM 的短命 Release helper 数据，验证首次签名与退出清理；如果不支持候选预算，
继续保持生产缓存关闭，先调查成本，不放宽事件合同。
